# 재접속 · 카카오톡 인앱 QA

첫 진입은 **익명 로그인**입니다. 익명 계정의 열쇠(Supabase 세션)는 **그 브라우저의 저장소(localStorage)에만** 있습니다.
그래서 "같은 브라우저"에서는 기록이 이어지고, "다른 브라우저·다른 기기·저장 정보 삭제"에서는 새 사용자로 시작합니다.
다른 브라우저에서 이어지게 하려면 계정 연결이 필요합니다(`docs/ACCOUNT_LINKING.md`).

## 확인 도구

- **`/dev/session`** (QA 전용, 제품 화면에서 링크 없음): 브라우저 종류, 사용자 ID 끝 8자리, 러닝 동물, 온보딩 완료, 러닝 기록 수, 저장한 신발 수, PostHog ID 일치 여부.
  새 사용자를 만들지 않습니다(세션이 없으면 "없음 — 새 사용자").
- 시험 전 각 브라우저에서 `?qa=1`로 한 번 열어 QA 표시를 켭니다(분석 제외).
- 링크: Preview 또는 Production 주소 + `/dev/session?qa=1`

## 공통 절차 (브라우저 A → B)

1. A에서 `https://<주소>/?qa=1` → 테스트 → Reveal → 프로필 → 신발 → RUNNING
2. A에서 러닝 1건 저장, ITEMS에서 신발 1개 저장
3. A에서 `/dev/session` → 화면 캡처 (사용자 ID 끝 8자리 등)
4. B에서 같은 주소 `/` 열기 → 어디로 가는지 기록 → B에서 `/dev/session` → 캡처
5. 아래 표의 "예상"과 비교

### 버그로 볼 것 (정상 제약 아님)

- 같은 브라우저(#1, #7)인데 사용자 ID가 바뀜 → 세션 저장·갱신 문제
- 사용자 ID는 같은데 동물·기록·Saved가 비어 있음 → 서버 조회 또는 RLS 문제
- PostHog ID가 사용자 ID와 "불일치" (QA 켜진 상태) → identify 문제
- 온보딩을 끝냈는데 `/`에서 Landing이 보임 → 재방문 진입 로직 문제
- 로딩 실패 화면에서 "다시 시도"로 회복되지 않음

### 정상 제약의 이유

- **앱마다 저장소가 따로**: 카카오톡 인앱 브라우저(iOS WKWebView, Android WebView)는 Safari·Chrome과 쿠키·localStorage를 공유하지 않습니다. 링크를 다른 앱에서 열면 다른 브라우저와 같습니다.
- **Safari의 저장 기간 제한(ITP)**: iOS Safari는 사이트와 **7일간 상호작용이 없으면** 스크립트로 쓴 저장소(localStorage 포함)를 지울 수 있습니다. WKWebView 기반 앱 안의 브라우저에도 적용될 수 있어 **실기기 확인 필요**합니다. 홈 화면에 추가한 웹앱은 예외입니다.
- 익명 계정에는 이메일·카카오 같은 "다시 찾을 열쇠"가 없으므로, 열쇠(세션)를 잃으면 서버 기록을 되찾을 방법이 없습니다. URL에 사용자 ID를 넣어 복원하는 방식은 보안상 쓰지 않습니다.

실기기(#2~#8)는 카카오톡·iPhone·Android가 필요해 **미검증**입니다. 위 절차로 진행해 결과를 표에 채웁니다.
