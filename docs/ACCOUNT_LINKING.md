# 계정 연결 검토 (권장안 · 구현 전)

> 상태: **검토 보고**. 아직 구현하지 않았습니다. 사용자 승인 후 별도 PR로 진행합니다.

## 문제

- 첫 진입은 익명 로그인 → 기록은 서버(Supabase)에 있지만, 그 기록을 여는 열쇠(세션)는 **처음 쓴 브라우저에만** 있습니다.
- 카카오톡 인앱 ↔ Safari/Chrome, 다른 기기, 저장 정보 삭제, iOS Safari 7일 저장 제한 → 열쇠를 잃으면 새 사용자로 시작합니다 (`docs/QA_REVISIT.md`).
- 복구하려면 사용자가 "다시 증명할 수 있는 수단"(이메일, 카카오 계정)을 **기존 익명 계정에 연결**해 두어야 합니다.

## 원칙

- 첫 진입은 지금처럼 익명. 연결은 선택(예: 첫 러닝 기록 후 "기록 지키기").
- **기존 익명 계정에 로그인 수단을 붙이는 방식**(사용자 ID 유지) → 기록 이동·병합이 없고 RLS도 그대로.
- 하지 않는 것: URL에 사용자 ID를 넣어 공유·복원, 인증 없는 기록 복원, 기기 지문 같은 추정 식별.

## Supabase가 지원하는 방식 (공식 문서 확인, 2026-10-15)

| | 이메일 OTP | 카카오 로그인 |
|---|---|---|
| 익명 계정에 연결 | `auth.updateUser({ email })` → 받은 6자리 코드로 확인 → **같은 사용자 ID**가 영구 계정이 됨 | `auth.linkIdentity({ provider: "kakao" })` → 카카오 동의 → 같은 사용자 ID에 카카오 연결 |
| 다른 브라우저에서 복구 | `signInWithOtp({ email, options: { shouldCreateUser: false } })` → 코드 입력 | `signInWithOAuth({ provider: "kakao" })` |
| Supabase 설정 | Manual linking 켜기, 이메일 템플릿에 코드(`{{ .Token }}`) 사용, **사용자 지정 SMTP 필수** | Manual linking 켜기, Kakao provider 켜기(REST API 키·Client Secret·Redirect URI) |
| 외부 준비 | 메일 발송 서비스(AWS SES, Resend 등) + 발신 도메인 인증 | Kakao Developers 앱. 이메일 동의항목(`account_email`)은 **비즈 앱**만 가능 → 없으면 "이메일 없는 사용자 허용" |
| 카카오톡 인앱에서 | 코드 입력이라 같은 화면에서 끝남. (링크 방식은 메일 앱이 다른 브라우저로 열어 **연결이 다른 브라우저에 생김** → 링크 방식은 쓰지 않음) | 카카오톡 안에서 동의가 자연스러움. Safari에서는 카카오 로그인 화면 또는 카카오톡 앱 전환 후 복귀(실기기 확인 필요) |
| 이미 다른 계정에 연결된 수단 | 연결 시도는 실패 → "기존 기록 불러오기"(로그인)로 안내 | 같음 (`linkIdentity` 실패 → `signInWithOAuth`) |
| 개인정보 | 이메일 주소 수집 → 수집·이용 안내 갱신 필요 | 카카오 회원번호(+선택 시 이메일·닉네임) → 안내 갱신 필요 |
| 비용·일정 | SMTP 설정 0.5일 + 화면·흐름 2일 | Kakao 앱·심사 준비 + 화면·흐름 2일 |

Supabase 기본 메일 발송은 **프로젝트 팀원 주소로만, 시간당 2통**이라 실제 사용자에게 쓸 수 없습니다 → 사용자 지정 SMTP가 전제입니다.

## 권장안

1. **1단계: 이메일 OTP 연결** (권장)
   - 외부 심사 없이 바로 가능하고, 카카오톡·Safari·Chrome 어디서나 같은 방식으로 복구됩니다.
   - 메일 발송은 회사 AWS를 쓰면 **AWS SES**(9번 AWS 검토와 함께 결정), 아니면 Resend.
   - 화면: Handoff에 시안이 없음 → **DECISION NEEDED**: 위치(MY PROFILE / 첫 기록 후 안내), 문구.
2. **2단계: 카카오 로그인 추가** (선택)
   - 카카오톡으로 유입되는 사용자가 많으면 편의용으로 추가. 비즈 앱 전환 여부 결정 필요.
3. **함께 검토**: 세션을 서버가 쓰는 쿠키로 옮기면(@supabase/ssr) iOS의 7일 저장 제한 영향을 줄일 수 있음 — 연결을 대신하지는 못함.

## 결정이 필요한 것 (DECISION NEEDED)

- 다른 브라우저에서 "기존 기록 불러오기"를 할 때 **그 브라우저에서 새로 만든 익명 기록**은? (권장: 합치지 않고, 불러오기 전에 "이 브라우저의 새 기록은 사라져요" 확인 → 실제 데이터 손실이므로 승인 필요)
- 연결 권유 시점과 화면 위치, 이메일 수집 안내 문구
- 메일 발송 서비스(AWS SES / Resend)와 발신 주소
- 카카오 비즈 앱 전환 여부

## 구현 시 지킬 것

- RLS 정책은 그대로(사용자 ID가 바뀌지 않음). 연결 전후 `npm run test:rls`.
- OTP 요청 횟수 제한(Supabase Auth rate limit) 확인, 봇 방지(CAPTCHA)는 8번 보안 점검과 함께.
- PostHog `distinct_id`는 Supabase 사용자 ID 그대로 → 연결 후에도 같은 사람. 다른 브라우저에서 로그인하면 그 브라우저의 PostHog도 같은 ID로 identify.
- 이메일·카카오 정보는 PostHog·events로 보내지 않음(허용 목록 유지).
